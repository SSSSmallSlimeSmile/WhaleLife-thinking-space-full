# 思维空间 · 技能库插件

> **这份是留档，不是上游。** 它保留了技能壳的「长期免问」档（`approval: full`），作者在 issue #34 里要求取消。
> 为什么留、差在哪、怎么装，见 [SHELLS-FULL.md](SHELLS-FULL.md)。要跟作者版就别用这份。

WhaleLife 插件。把「一串工具调用」存成一条可复用的技能，之后一句 `space_run` 就能跑完整条链，不用让模型每一步都重新推理一遍。

技能定义存在服务端 `data/skills.json`，模型和页面读同一份。跑一次省下来的不是时间——是**中间每一步的上下文重传**。

---

## 发布成技能壳

把一条技能注册成**常驻工具**，普通对话里直接能调，不用先检索再 `space_run`。

**入口只有一个**：技能列表页（`/plugins/thinking-space/space`）右上角的「生成壳 →」，进去是 `/plugins/thinking-space/shells/`。画布上那个「发布到思维空间」发的是**技能**，不是壳。

### 它是什么

- **一个固定子插件 + 一份数据**。程序只有 `sub/shells/` 这一份，随包发布，运行时不写任何程序文件。加壳、删壳只动它自己的 `data/shells.json`：写一条记录、注册一个工具。
- **不用重载**。加壳当场出现在工具表里，删壳当场注销；重启宿主时按记录自动注册回来。
- **壳里不存技能内容**，只留技能 id、工具名、危险等级和发布那一刻的版本号。运行时按 id 调 `space_run`——技能改了，壳自动跟着变。
- **参数跟着技能走**。壳的工具 schema 不是写死的空对象，而是按技能声明的 `params` 生成：类型、必填、说明都来自技能自己。别名映射回正名，没声明的字段过滤掉。
- **不跨插件读磁盘**。技能声明由父插件通过公开服务 `thinking-space.skills` 提供（`describe()`），壳启动时取一次。服务不在就退回 `space_skills` 工具——那时只有摘要、没有参数，壳照旧能建，只是不带入参，不瞎猜。
- **危险等级从技能推导**，壳不能给自己降级。
- 页面 `/plugins/thinking-space/shells/`；数据文件 `sub/shells/data/shells.json`。

### 代价

发布之前先掂量这几条：

- **每轮常驻**。壳的工具定义跟着每一次请求发给模型，不管这一轮用不用得上。壳越多，工具表越长，小上下文的模型越容易被挤满。
- **技能改了，壳不会自己重新注册**。参数声明变了要重载子插件；回执里会提示版本对不上，但不会自动同步。
- **所有壳共用一个进程**。以前一个壳一个子插件，崩一个不影响别的；现在这个进程挂了，所有壳一起消失。
- **依赖一个没写进契约的能力**。apply 之后动态注册/注销工具，本机实测可用，但作者没把它写进契约。

所以顺序是反的：**先跑熟，再固定。** 一条技能一个月跑三次，用技能组就好；一周跑几十次、或者必须让危险等级显式摆在模型面前，才值得做成壳。

## 一、它能做什么

| 工具 | 用途 |
|---|---|
| `space_skills()` | 列出技能：ID、名称、步数、权限、状态、跑过几次、上次成败、版本号；另外返回开关状态和自动整理线索 |
| `space_skill_save({ id, spec })` | 新建或覆盖同 ID 的技能，校验不过返回 `blocked` 和具体原因 |
| `space_draft({ name, tools })` | 给一串工具名，自动查归属插件、声明必填参数、连 `next` 链，生成草稿并预校验（不保存） |
| `space_run({ id, params, confirmSideEffects })` | 真跑一遍，返回逐步回执 |
| `space_trace({ runId, recent })` | 按 `runId` 取回一次运行的完整步骤（内存留一小时） |
| `space_organize({ force })` | 从最近的工具调用记录里找反复出现的工具链，整理成技能 |
| `space_ports({ tool })` | 从记录下来的返回值形状反推每个工具的输出端口和类型，供拼技能时查「上一步哪个字段能接下去」。是观测不是声明：`trusted` 只在同一形状出现过三次以上时为真 |

页面：

| 路由 | 内容 |
|---|---|
| `/plugins/thinking-space/` | 介绍、当前状态、设置（唯一入口，也接管导入回执） |
| `/plugins/thinking-space/space` | 功能库 / 复合功能库列表，每条可「跑一次」「编辑步骤」 |
| `/plugins/thinking-space/edit?id=` | 改步骤：参数 JSON、上移 / 下移 / 删除、新增一步 |
| `/plugins/thinking-space/export` | 导出全部技能为 JSON |

## 二、怎么装

### 一条命令（推荐）

Release 里的包是 `.wlpkg.gz`（gzip + 首行清单 + 内容），普通解压工具打不开。
用仓库根的 `install.mjs` 下载、校验、释放：

```bash
node install.mjs --host "<宿主目录>"
```

它做四件事：

```
下载 thinking-space-<版本>.wlpkg.gz（版本号见 plugin.yaml，<版本> 填当前值）
逐文件比对 sha256（不一致就停，不写半个文件）
释放到 <宿主>/plugins/thinking-space
写 data/install.json 记录版本、来源、包摘要
```

参数：

| 参数 | 作用 |
| --- | --- |
| `--host <目录>` | 宿主根目录（下面要有 `plugins/`）。省略时用当前目录 |
| `--file <包路径>` | 用本地包，不联网 |
| `--force` | 覆盖已存在的插件目录（原有的 `data/` 内容保留） |

装完重启宿主，或到插件页点一次 reload。

### 手动装

仓库根就是插件目录，也可以 clone 或解压 zip 到 `plugins/thinking-space`：

```bash
git clone https://github.com/SSSSmallSlimeSmile/WhaleLife-thinking-space.git plugins/thinking-space
```

```
plugins/thinking-space/
  plugin.yaml          depends: [web, tools, models]
  index.ts
  install.mjs          一键安装脚本
  data/settings.example.json
  sub/canvas/          思维画布（子插件，独立的 node 进程）
  sub/comfy-bridge/    思维画布桥（子插件，列工作流与功能包、给别的软件当中转）
  docs/                技术说明与实测数据
```

**依赖**：`web`（注册页面和 POST 接口）、`tools`（工具目录与技能执行）、`models`（技能里的 `llm` 步骤要用）。
缺 `models` 不会拦住启动，但带模型提炼的技能会报「没有可用的对话模型」——这是最容易踩的一个坑。

**装好后重启宿主**，导航「插件页面」里会出现「思维空间」。插件通过 `navigation: true` 自报导航，
不用改宿主任何文件。早期版本需要手改 `core/ui/index.html` 那套硬编码已经撤掉了。

**可选绑定**：技能里用到的工具得在宿主里存在，否则保存时校验不过。常用的是 `surf_search` / `surf_read`（装 `surf`）。

## 三、技能长什么样

```json
{
  "schemaVersion": 1,
  "name": "搜资料",
  "kind": "composite",
  "description": "搜索并读取首条可读网页",
  "params": [
    { "name": "query", "label": "关键词", "type": "string", "required": true,
      "aliases": ["关键词", "q"] }
  ],
  "steps": [
    { "id": "n1", "tool": "surf_search", "plugin": "surf",
      "params": { "query": "${query}", "limit": 3 }, "next": "n2" },
    { "id": "n2", "tool": "surf_read", "plugin": "surf",
      "params": { "url": { "$try": [
        "${n1.data.results[0].url}",
        "${n1.data.results[1].url}",
        "${n1.data.results[2].url}"
      ] } }, "next": null }
  ]
}
```

三条要记的规则：

**一、占位用 `${...}`，数组下标用方括号。** `${n1.data.results[0].url}` 对，`${n1.data.results.0.url}` 会被校验器拦下并指出是哪一步写错。

**二、参数名用工具 schema 的机器名，人看的名字放在 `label`。** `query` 是机器名，「关键词」是标签，`aliases` 收旧写法。同一个参数三套名字并存，是我自己踩过的坑——调用时写成工具的字段名，页面显示中文标签。

**三、`{"$try": [...]}` 是候选回落。** 按顺序试，第一个成功的采用；每个候选的成败都进回执。适合「第一条搜索结果读不了就换第二条」。

## 四、运行状态：五态

| 状态 | 含义 | 该怎么做 |
|---|---|---|
| `ok` | 正常 | — |
| `failed` | 这一步可重试 | 看 error 决定 |
| `uncertain` | 结果未知（单步超时） | **不要自动重试**，可能已经产生副作用 |
| `blocked` | 缺前置条件（技能不存在、缺必填参数、含未确认的副作用步骤） | 补条件再跑 |
| `skipped` | 这一步没成，但后面的步骤不依赖它，已继续 | 看整体回执 |

**全部步骤都叫 `skipped` 时，整体抬成 `failed`**——一步都没干成，报「跳过」会让人以为没事。

**单步超时**（默认 60 秒，可设 1–600）只是不再等，不中断底层调用。所以超时记的是 `uncertain`，不是 `failed`。

### 业务失败识别

插件工具的常见写法是返回 `{ ok: true }`，然后在正文里写「服务没起」「显存不够」。执行器会看输出里的文字：

```
强词（任意长度 ≤300 字）  没在跑 / 未启动 / 已停止 / 显存不够 / 低于阈值 / 请先启动 …
弱词（仅 ≤60 字短句）      失败 / 错误 / 无法 / 找不到 / 拒绝 / error / failed / denied
```

长正文不参与弱词判定——`surf_read` 读回来的几千字里出现「错误处理」不会误判。宁可漏判，也不错杀。

## 五、自动整理（「学会技能」）

开着时，插件监听 `tool/called` 事件，记录工具名和成败：

```
排除     space_*（自己）、hands_*（动手类，永远会被跳过）、transient 调用只记名字不记参数和结果
窗口     默认留最近 800 条
```

整理时：

```
按会话分组 → 按时间排序 → 间隔超过窗口（默认 120 分钟）就断开 → 切 2~5 步 n-gram
→ 出现次数 ≥ 阈值（默认 3）→ 技能库里还没有同样工具序列 → 存成 auto-<hash>，每次最多 3 条
```

三条去重规则（都是踩过坑补的）：

**一、周期折叠。** `a,b,a`、`a,b,a,b` 能由 `a,b` 重复拼出来的，丢掉长的那条。第一版没做，连做三轮同一组合就生成 2 步 / 3 步 / 4 步三个版本。

**二、错位周期。** 判定得检查所有偏移量，否则 `[surf, ledger, surf]` 和 `[ledger, surf]` 认不出是同一个循环。

**三、反向折叠。** 链里没有 `hands_` 这类顺序敏感工具时，`a→b` 和 `b→a` 等价，只留一条。`hands_write → hands_run` 和反过来不是一回事，不能折。

**含确认步骤的链默认不存**，除非设置里打开「允许整理含确认步骤的链」。打开了也只是存下来，跑的时候到那一步仍会停下来征求同意。

## 六、自动精简（跑熟了会变短）

跑通一次，就回头看这条链有没有哪一步白跑。

**删步骤**（四条全满足）：这一步跑成了 · 输出没被后面任何一步引用 · 不是最后一步 · 工具不需要确认。

有副作用的步骤永远不会被自动删。删到只剩 2 步就停手，所以 4 步的链是逐步变短的：

```
跑一次  4 → 3
再跑   3 → 2
```

**砍候选**：连续 3 次都是 `$try` 的第一条命中，就砍掉后面从没命中的候选，清掉计数不反复触发。

每次改写版本号 +1，回执里带 `trimmed: { from, to, dropped, revision, cut }`，页面显示「这条技能跑完自己缩短了」。

## 七、设置项

| 键 | 默认 | 说明 |
|---|---|---|
| `allowSave` | 开 | 关掉后 `space_skill_save` 和导入一律 `blocked` |
| `allowUse` | 开 | 允许在对话里使用已保存的技能。关掉后 `space_run` 一律 `blocked` |
| `autoOrganize` | 开 | 自动整理的总开关；关掉后 hints 不出现，但调用统计照记 |
| `spaceUrl` | `http://127.0.0.1:9281/` | 「打开思维空间」按钮指向的画布地址，只认 http/https，≤300 字 |
| `maxSteps` | 20 | 单条技能最多步数，1–20，只影响新保存 |
| `organizeThreshold` | 3 | 同一工具链出现几次才算一条 |
| `organizeWindowMinutes` | 120 | 两次调用隔多久算断开，5–1440 |
| `autoSaveOrganized` | 开 | 整理出的技能直接存；关掉就只在报告里列出来 |
| `allowRiskyChains` | 关 | 允许整理含确认步骤的链 |
| `learnOnRequest` | 开 | 让助手知道「用户说一句话时就该去整理」 |
| `triggerPhrase` | `XXX，你学会这个技能了吗？` | 那句话本身，`XXX` 换成人格名 |
| `stepTimeoutSeconds` | 60 | 单步超时，1–600 |
| `observeHands` | 关 | 是否记录 `hands_*` 类工具的返回值形状。开着也只记键名和类型（如 `{ok:b,result:s}`），不记路径、不记正文 |

**`learnOnRequest` 和 `triggerPhrase` 只是把状态带给模型，插件本身不监听对话。** 听不听那句话，是模型负责的事。

## 八、数据文件

```
data/skills.json          技能库（唯一真源）
data/settings.json        设置；出厂值见 data/settings.example.json
data/stats.json           每条技能的运行次数、失败原因分桶、候选命中统计
data/calls.json           最近的工具调用记录（自动整理 + 端口推断用，默认 800 条上限）
data/failures.json        最近的失败原因（最多 200 条，排查用）
data/param-defaults.json  可选：给没写默认值的必填参数补一份，只影响自动整理学出来的技能
```

都是纯 JSON，可以直接看、直接备份。除 `settings.example.json` 外，仓库里不带这些文件——克隆下来是干净的技能库，没有别人的调试记录。

### 本机能力页（可选）

设置页「当前状态」里有「查看本机能力 →」，打开 `/plugins/thinking-space/local`。

它把当前宿主的工具目录整个列出来：按插件分组、每个工具的危险级、有没有声明输出结构，顶部徽章标出这台宿主提供的是 `catalog()` 还是降级的 `list()`。换台机器、装了新插件，点开就知道自己有什么、缺什么。

同一页有「整理本机能力」按钮。扫一遍工具和技能，记下：哪些工具还没被任何技能用过、哪些插件有空闲工具、多少工具没声明输出结构。结果写进 `data/local-report.json`，下次打开还在，页面上显示上次整理的时间和结论。

这一步只读——只看工具目录和技能库，不改任何技能、不改任何插件。

## 九、已知限制

**一、页面只能验 HTML，验不了排版。** 我没法看浏览器，只能确认接口返回的元素在不在。

**二、「管理」导航组要手改**（第二节那条）。

**三、自动整理学到的技能不一定能直接跑。** 它不知道该给参数填什么，只能声明为必填。这类技能当模板用，跑之前要补参数。

**四、调用记录从插件启动开始算。** 插件启动前的调用没有历史；想要旧数据得另读会话记录。

**五、`uncertain` 态只真撞过一次**，用超时造的。真工具卡死时的行为没验证过。

**六、单步超时不中断底层调用。** 只是不再等。

**七、`comfy_generate` 这类常驻 GPU 的工具，第二次出图可能因为显存没释放被自己的阈值拦住**，跟技能库无关。

**八、画布的启停只在 Windows 验证过。** 画布是子插件，查端口、结束进程走的是 `taskkill` 和 PowerShell，Linux / macOS 上「启动画布 / 停止」会失败；技能库、执行器、页面、自动整理不依赖平台。

**九、画布进程跟着子插件收。** 画布是 detached 起的，子插件 stop 时按手上的进程句柄直接结束（父插件停 → 子插件停 → 画布收）；设置页那个开关可以关掉这个行为。**收尾只有 1 秒预算**（宿主 `stopTimeoutMs` 默认 1000，超时 SIGKILL），所以这段里不能跑 PowerShell 之类的慢调用。重载父插件等于停用+启用，画布也会被收掉。在外面手动起的画布不归它管，得自己停——不过画布带着 `--parent-pid` 看护，宿主没了会自己退出。

## 十、画布（子插件）

画布是包里的子插件 `thinking-space/canvas`：目录在 `plugins/thinking-space/sub/canvas/`，
运行时 id 是 `thinking-space/canvas`，随父插件一起装、一起启用。

它自己管一个 node 小服务（`sub/canvas/whalelife-workbench.cjs`，默认监听 9281），把画布页面和宿主连起来。
启停、端口、脚本路径都在「思维画布」那一页（父插件卡片下面的子插件），不再塞在思维空间的设置页里。

**端口和宿主地址**：都在子插件设置页里。端口默认 9281；宿主地址打开页面时自动填当前 origin，
你确认一次保存即可。没设、或者设了连不上，都不启动——不猜默认端口，也不读宿主的配置文件。
两个实例一起跑时，各填各的地址，不会互相连错。

地址里的**子路径会保留**：宿主挂在 `http://127.0.0.1:9272/review-prefix` 时，探活和所有转发
（`/plugins/…`、`/api/status`、`/market/…`、WebSocket）都走 `/review-prefix/…`，不会被砍成根路径。
保存时只接受 `http(s)://主机:端口[/子路径]` 这种形式，别的直接拒。

**跟着思维空间走**：默认勾着「思维空间停掉时，画布一起收掉」。停用父插件时宿主先停子插件，
子插件再把画布进程收掉。不勾就各停各的，画布会挂到宿主退出或你手动停。

**三个工具**：`canvas_status`（只读）、`canvas_start`、`canvas_stop`（后两个要确认）。

### 技能组与发布

画布顶栏第四个标签「技能组」读宿主技能库（`GET /plugins/thinking-space/skills`），按功能组 / 复合功能组两块列出，只读，用来对照画布上的流程和库里实际存的技能。

画布上的流程点「发布到思维空间」会转成技能存进 `skills.json`（`POST /plugins/thinking-space/publish`）。技能只能引用上游某一步的**某个字段**，所以跨步骤连线要填字段路径（如 `data.text`），留空或写错宿主返回 422，原因原样显示、不保存。

### 注册功能（把画布外的东西搬进来）

工具栏「注册功能」把一个功能包做成流程：可以**选文件**（推荐），也可以粘 JSON。功能包就是画布的 `schemaVersion: 1` 导出物；不合格当场拒绝并逐条给原因，不留半条。

一条容易踩的：输入节点（`input_text` 这类）连进某个参数位，发布的技能会**把那个参数提成可填**（`${prompt}`）；而节点里直接写死的值是固定值。想让技能每次换提示词，就别把提示词写死在出图节点里。

### 依赖

- 需要 WhaleLife 宿主在跑（画布靠它取插件列表、市场目录、工具目录）
- 启停走 `taskkill` 和 PowerShell，**只在 Windows 验过**
- 画布自己每 3 秒探一次宿主端口，宿主没了会自己退出

### 相关命令

| 参数 | 作用 |
|---|---|
| `?flow=<流程id>` | 打开并居中的某条流程 |
| `?skill=<技能id>` | 把一条技能注入成节点并选中 |
| `?flow=<id>&node=<节点id>` | 顺便选中某个节点 |

画布和技能库的契约问题（端口声明、双向同步）见 [`docs/插件接入规范.md`](docs/插件接入规范.md)。

### 降级读取（旧宿主）

工具目录优先用 `ctx.tools.catalog()`，它带插件归属、危险级、输出声明。宿主没有这个接口时，自动退回 `ctx.tools.list()`：工具名和描述能用，插件归属、危险级、输出声明拿不到，画布端口会标「未声明」。

打开 `/plugins/thinking-space/local` 能直接看到这台机器走的是哪条路：顶部徽章写着 `catalog 可用` 或 `catalog 不可用`，清单里拿不到的字段显示「未声明」。都不可用时不报错，只是工具列表为空。

## 十一、思维画布桥（子插件）

包里的子插件 `thinking-space/comfy-bridge`，页面名「思维画布桥」，随父插件一起装。

它解决一个顺序问题：画布要能选「用哪个 ComfyUI 工作流」，但画布读不到生图插件的目录。
桥不直接读别人的目录——生图插件（`comfy` ≥ 0.3.1）用 `ctx.provide("comfy.assets", …)` 公开四个方法，桥订阅这个服务当中间层。
服务不在时桥照常起来，只是说「当前版本不支持自动列出工作流」，手动导入照常。

- 列 `plugins/comfy/workflows/` 下的工作流，和 `plugins/comfy/canvas-flows/` 下画布可直接导入的功能包
- 包里 `workflow` 指向的文件不存在时标红，并写出缺哪个
- 体检：生图插件在不在、`comfy_generate` 注册没、工作流/功能包数、缺工作流的包数、画布地址
- 每个功能来源一块折叠区，默认收起；ComfyUI 是内置那一块

**依赖写的是 `depends: [web]`，不是 `[comfy]`。** 宿主的 `depends` 认的是服务名，生图插件不 `provide` 任何服务，写 `[comfy]` 会永远 `blocked 等待依赖：comfy`。所以生图插件改成运行时探：没装时桥照常起来，只是列不出工作流，页面上写明要先装什么。

**给别的软件当中转**（ComfyUI 扩展、Blender 脚本、随便什么能发 HTTP 的）：

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/plugins/thinking-space/comfy-bridge/api` | 清单：端点、模板、校验规则 |
| GET | `/plugins/thinking-space/comfy-bridge/flows` | 可导入的功能包列表 |
| POST | `/plugins/thinking-space/comfy-bridge/providers` | 注册来源 `{id,name,description,fields}` |
| POST | `/plugins/thinking-space/comfy-bridge/import` | 推功能包 `{provider,name,bundle}` |

推上来的包**先过画布那套校验**，过不了直接 400 并逐条给原因，不落盘。同名直接覆盖——同一软件反复导出，要的是最新那份。

**设置**：只列能通过校验的包（默认开）、默认工作流（只影响提示）、画布地址（默认 `http://127.0.0.1:9281`）。

**删包**只认 `canvas-flows/*.json`，路径先 resolve 再前缀比对；删来源不删包。

桥自己的说明、功能文件模板和注意事项见 [`sub/comfy-bridge/README.md`](sub/comfy-bridge/README.md)。
